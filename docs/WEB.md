# allAI

Русскоязычная библиотека нейросетей и единый текстовый чат. React 19, Vinext, Cloudflare Worker и D1. Интерфейс Material You: адаптивная сетка, светлая и тёмная темы, мобильное меню.

## OpenRouter: быстрый запуск

Интеграция использует официальный TypeScript SDK `@openrouter/sdk` и endpoint `https://openrouter.ai/api/v1`. Общая серверная функция — `lib/openrouter.ts`; её вызывают и `/api/chat`, и пробная CLI-команда. Документация: https://openrouter.ai/docs/quickstart.

1. Создай API key на https://openrouter.ai/keys.
2. Перейди в эту папку `allai` и установи зависимости командой `npm ci`, если они ещё не установлены.
3. Задай `OPENROUTER_API_KEY` в окружении терминала. Для локального запуска сайта можно вместо этого скопировать `.env.example` в `.dev.vars` и вписать ключ туда. Этот файл исключён из Git; не добавляй ключ в исходники и не используй переменную с префиксом `NEXT_PUBLIC_`.
4. Выполни:

```sh
npm run openrouter:smoke
```

По умолчанию команда делает один реальный запрос к `openrouter/free`, выводит фактически выбранную модель и её ответ. Бесплатные модели имеют ограничения доступности и частоты запросов. Другую модель можно указать её slug из https://openrouter.ai/models:

```sh
npm run openrouter:smoke -- anthropic/claude-opus-5.5 "Ответь одной фразой: что такое API?"
```

Наличие модели и право доступа определяет OpenRouter. Платный запрос расходует баланс твоего ключа. Модель также можно задать через `OPENROUTER_MODEL`. CLI читает ключ из окружения, а если его там нет — из локальных `.dev.vars`, `.env.local` или `.env`. Ключ никогда не выводится в консоль. Без ключа, при HTTP-ошибке, таймауте или пустом ответе команда завершится с ненулевым кодом и понятным сообщением. Автоматические повторы генерации отключены.

Для сайта: `npm run dev`, войди в аккаунт, открой новый чат, выбери Free Router и отправь сообщение. Worker получает серверный ключ из `env.OPENROUTER_API_KEY` (локально — из `.dev.vars`, на хостинге — из runtime secret). Серверный ключ предназначен только для бесплатных моделей; для платных моделей пользователь вводит свой ключ в настройках.

Проверки без расходования баланса:

```sh
npm run test:api
npm run build
```

API-тест вызывает настоящий SDK с имитацией HTTP-ответов OpenRouter и временной D1: проверяет передачу ключа, model slug, историю диалога, HTTP 401/402/403/404/429/500, пустые ответы и отсутствие ключа в сообщениях об ошибках. Это не подтверждение успешного запроса к живому провайдеру.

## Возможности

Десктопный клиент для Windows, macOS и Linux находится в [desktop](../desktop/README.md). Установка зависимостей клиента: `npm run desktop:install`, запуск: `npm run desktop:dev`. Сборки для трёх систем — через workflow **Desktop builds** в GitHub Actions. Клиент подключается к тому же серверу, для работы нужен интернет.

- Базовая библиотека популярных сервисов, поиск, категории, избранное на устройстве.
- Обновление текстовых моделей, контекста и цен через публичный API OpenRouter, кеш 5 минут. При недоступности API остаётся базовый каталог, это явно указано в интерфейсе. Каталог не претендует на полный перечень всех существующих нейросетей.
- Регистрация/вход по почте и паролю, PBKDF2, HttpOnly Secure cookies, проверка Origin и ограничение попыток входа. Почта не подтверждается; восстановление пароля по письму пока не реализовано.
- Google OAuth подключается после настройки переменных ниже. Аккаунты с паролем автоматически не объединяются с Google.
- Авторизация через аккаунт ChatGPT поддерживает предоставляемую Sites идентификацию.
- Сохранённые на сервере личные диалоги и смена модели с передачей всей истории. При превышении лимитов запрос отклоняется без скрытого удаления истории. Контекстные ограничения определяет провайдер. Ответ появляется после завершения генерации, streaming пока не подключён.
- Общая комната пользователей, хранение в D1, обновление каждые 5 секунд; личные сообщения пока не реализованы.
- OpenRouter API key хранится исключительно в памяти вкладки, передаётся серверу только при запросе и не записывается в базу. Это ключ агрегатора, прямые ключи OpenAI/Anthropic сюда не подходят.
- Изображения, видео и аудиосервисы представлены справочными карточками со ссылками. Генерация этих медиа внутри allAI пока не подключена.

## Ключи и Google

В Sites настрой runtime secrets (не в исходниках):

| Переменная | Назначение |
| --- | --- |
| `OPENROUTER_API_KEY` | Бесплатные тесты без пользовательского ключа; сервер допускает только модели с нулевой ценой или `openrouter/free`. Действуют лимиты OpenRouter. |
| `GOOGLE_CLIENT_ID` | OAuth Web Client ID |
| `GOOGLE_CLIENT_SECRET` | OAuth Client Secret |

Google redirect URI: `https://allai-library-ruslan.rainyhedgehog.chatgpt.site/api/auth/google/callback`. В Google Cloud включи OAuth consent screen и добавь разрешённых тестовых пользователей до проверки приложения. После изменения secrets перевыпусти сохранённую версию сайта, чтобы настройки применились.

Новый Site опубликован приватно для владельца. Внешние посетители и сообщество между разными людьми потребуют изменения аудитории в настройках Sites; код авторизации приложения и проверки владельца каждого чата уже предусмотрены. Не меняй аудиторию без решения владельца.

## Разработка

Рабочая директория — эта папка `allai`. Node >=22.13.

```sh
npm ci
npm run dev
```

Сборка: `npm run build`. Миграции D1: `npm run db:generate`, затем применить SQL к локальной базе через Wrangler (см. DEVELOPMENT.md). Миграции опубликованной базы применяет Sites.

## Проверки

`node node_modules/typescript/bin/tsc --noEmit`

`node scripts/check-api.mjs`

API-проверка использует отдельную временную D1 через Miniflare и имитирует ответ OpenRouter: регистрация, вход/выход, cookies, CSRF, сохранение сообщений, смена модели с полной историей, изоляция двух аккаунтов, общая комната и throttling. Реальные AI-ответы требуют ключа и отдельно не подтверждены.
